TRAINING THE LINEAR A SIGN DETECTOR
===================================

What this does
--------------
Trains a YOLO model to draw boxes around Linear A signs on tablet drawings, and
labels each box with the sign's role: syllabogram, logogram, fraction or
transaction. The backend's HT 13 demo uses the trained model automatically,
and boxes labelled "fraction" also get shape-matched guesses (J, E, ...).

The training data is built from the lineara.eu drawings already in the repo
(fraction-solver/data/). No hand labelling is needed.

Time: about 30 minutes of setup, 10 minutes to build the dataset, and roughly
30-60 minutes of training on a laptop GPU (RTX 3060 class). Without an NVIDIA
GPU training takes 8-16 hours; use Google Colab instead (see the end).

Commands below are for Windows PowerShell, run from the repository root unless
a step says otherwise. On macOS/Linux, replace "\Scripts\" with "/bin/".


STEP 0. Before you start
------------------------
  - Plug the laptop in. On battery the GPU runs much slower.
  - Close Chrome tabs and other apps you do not need. Training needs about
    4-6 GB of free RAM. Check in Task Manager > Performance > Memory.
  - Have about 6 GB of free disk space.
  - Check the GPU is visible:

        nvidia-smi

    It should list your NVIDIA GPU. If the command is not found, install the
    NVIDIA driver first.


STEP 1. Get the code and data
-----------------------------
        git fetch
        git switch 6-tablet-reading
        git pull

  The tablet drawings are in fraction-solver/data/images/ (731 tablets,
  4,836 sign drawings). The starting model, yolo26n.pt, is at the repo root.


STEP 2. Create a training environment (one time, about 15-20 minutes)
---------------------------------------------------------------------
  This is separate from the backend's environment, so it cannot break the app.

        python -m venv .venv-train
        .venv-train\Scripts\python -m pip install --upgrade pip
        .venv-train\Scripts\python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
        .venv-train\Scripts\python -m pip install "ultralytics>=8.4,<9.0"

  The torch download is about 3 GB.

  Check that PyTorch can see the GPU:

        .venv-train\Scripts\python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

  Expected: True NVIDIA GeForce RTX 3060 Laptop GPU (or your GPU's name).
  If it prints False, the CPU-only build was installed; rerun the torch line
  above with --force-reinstall.


STEP 3. Build the dataset (about 10 minutes)
--------------------------------------------
        cd fraction-solver
        ..\.venv-train\Scripts\python -m la.cli dataset --labels role --workers 2
        cd ..

  This writes fraction-solver/out/yolo_signs/ with three splits, by tablet:

        train  ~70%  what the model learns from
        val    ~15%  what training uses to pick the best epoch
        test   ~15%  untouched until the final score (HT 13 is always here)

  A tablet is never split across two sets, so scores are not inflated by a
  scribe's hand appearing in both. The split is the same every time you
  rebuild. Expect this summary:

        Tablets: train 501, val 124, test 106 (always test: HT 13)
        Boxes:   train 3168, val 782, test 774
        Crops rejected (ink did not line up): 5
          syllabogram  3206
          logogram     1157
          fraction     304
          transaction  57

  "transaction" has very few examples, so expect a weak score for that class.

  --workers 2 keeps memory use low. With plenty of free RAM, use 4.


STEP 4. Train (about 30-60 minutes on a laptop GPU)
---------------------------------------------------
        .venv-train\Scripts\yolo detect train data=fraction-solver/out/yolo_signs/data.yaml model=yolo26n.pt imgsz=1024 epochs=100 patience=20 batch=8 workers=2 device=0 project=runs/detect name=linear_a_signs exist_ok=True

  What the settings mean:
    imgsz=1024    image size. Must stay 1024: the backend uses the same size.
    epochs=100    at most 100 passes over the training set.
    patience=20   stop early if the val score has not improved for 20 epochs.
    batch=8       images per step. Lower it if you run out of memory.
    device=0      use the first GPU.

  Each epoch prints a progress bar, then a line with P, R, mAP50 and
  mAP50-95 on the val set. Those numbers should rise over the first epochs.
  The first epoch also tells you the real speed: multiply its time by 100
  for the worst case.

  Ultralytics may download a small font file the first time; that is normal.

  If training stops (crash, laptop sleeps), resume where it left off:

        .venv-train\Scripts\yolo detect train resume model=runs/detect/linear_a_signs/weights/last.pt

  Output: runs/detect/linear_a_signs/weights/best.pt (the best epoch on val).


STEP 5. Score it on the test set
--------------------------------
        .venv-train\Scripts\yolo detect val model=runs/detect/linear_a_signs/weights/best.pt data=fraction-solver/out/yolo_signs/data.yaml split=test imgsz=1024 batch=8 device=0

  Write down the "all" row: P (precision), R (recall), mAP50 and mAP50-95,
  plus the per-class rows. These are the numbers to report: the test tablets
  were never used for training or for choosing the epoch.

  Rough reading of mAP50: above 0.8 is good, 0.5-0.8 is usable, below 0.5
  needs more work.


STEP 6. Install the model in the app
------------------------------------
        mkdir models
        copy runs\detect\linear_a_signs\weights\best.pt models\linear_a_signs.pt

  Start the app (npm run dev) and open http://localhost:5173/tablet-demo,
  or check the API directly:

        http://127.0.0.1:8000/tablet-demo/ht13/predictions

  It should now say "trained": true and list predictions. HT 13 is in the
  test split, so what you see is an honest result on an unseen tablet.

  Note: the right-hand list on the Tablet Demo page still shows hard-coded
  placeholder symbols. The boxes on the tablet image are the real ones until
  that page is fixed.


STEP 7. Share it
----------------
        git add models/linear_a_signs.pt
        git commit -m "[ADD] Trained Linear A sign detector"
        git push

  Put the test scores from step 5 in the commit message or the group chat.
  Keep the credit line with the weights: they are trained on SigLA /
  lineara.eu drawings (CC BY-NC-SA 4.0).


Troubleshooting
---------------
  "CUDA out of memory"      rerun step 4 with batch=4 (or batch=2).
  Windows freezes / swaps   close apps, use workers=0 in step 4 and
                            --workers 1 in step 3.
  Very slow epochs          check the laptop is plugged in and that step 2's
                            check printed True. GPU temperature above ~85 C
                            makes it slow down; improve airflow.
  "No module named la"      run step 3 from inside fraction-solver/.
  Scores near zero          make sure step 3 was run with --labels role and
                            finished without errors.


Known limits
------------
  - Numerals (tally strokes) have no labels, so the model will not box them.
  - It learns from clean drawings; it will not work well on photos of
    real tablets without photo training data.


No NVIDIA GPU? Use Google Colab
-------------------------------
  1. Zip fraction-solver/out/yolo_signs/ (after step 3) and yolo26n.pt, and
     upload both to Google Drive.
  2. In Colab: Runtime > Change runtime type > GPU.
  3. Run: !pip install "ultralytics>=8.4,<9.0"
  4. Unzip, fix the "path:" line in data.yaml to the Colab folder, then run
     step 4's command with "!yolo" instead of ".venv-train\Scripts\yolo".
  5. Download runs/detect/linear_a_signs/weights/best.pt and continue at step 6.
